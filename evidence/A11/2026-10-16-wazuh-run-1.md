## Review notes

1. The real Keycloak line in the report confirms the format the rules assume: logger `org.keycloak.events`, level `WARN`, and a message starting with `type="LOGIN_ERROR"`. Rule 100100 was written before this format was seen; it matched on the first run.
2. WZ-03 and WZ-04 used lines written by Keycloak during the run, not lines written by hand.
3. WZ-05 is weak evidence. "rule none" is what the script also reports if the API call fails or if the line is empty, so the run does not show that the line was read and rejected by the rules. The test was changed after this run: it now requires a non-empty line, a successful API call and the JSON decoder in the answer. WZ-05 counts as evidence only from the next run that passes.

## What this evidence shows and does not show

It shows that, in the lab on the date above, the built-in Wazuh rules raise SSH password-guessing alerts, and that the Lagune rules raise an alert for each failed Keycloak login and a level 10 alert after 5 failures in a session. WZ-05 is not accepted from this run (note 3).

It does not show that Keycloak logs reach Wazuh by themselves: the logtest API receives the lines from the test script. It does not detect a slow attack on a single account, since the rules do not extract the user name. The SoA status of the controls is not changed, because Lagune Payroll is fictional.
